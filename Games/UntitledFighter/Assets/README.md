# The title's content root

Everything Untitled Fighting Game ships that is not code. This directory is an
**asset root**, and the root `CMakeLists.txt` layers it on top of the engine's
(`Editor/src/Exported/`) into the single runtime `Exported/` beside the
executables — engine first, title second, later winning. The convention is
`Games/<title>/Assets`, gated on the title's player target existing, so composing
a title's content costs the same one line as composing its code.

**This file is not staged and neither is any other loose file here.**
`cmake/stage_runtime_assets.cmake` copies *subdirectories* and seeds *top-level
`.json`*, and a `.md` is neither.

## What is here, and why each one sits where it does

```
Characters/                 fighter_a.json, fighter_a_infinite.json, schema.v2.json
UntitledFighter/menu.json   the front end the host boots
UntitledFighter/UI/         its markup, stylesheet and art
```

### `Characters/` deliberately shares the engine's namespace

It stages to `Exported/Characters/`, which is exactly where it staged from when
it lived in `Editor/src/Exported/Characters/` <!-- docs-ok: names where it used to be, on purpose -->. That is the point: the source
moved, the **staged path did not**, and so seven readers went on working with no
edit at all — `UntitledFighterMode.cpp`, `ComboProverPanel.h`, and the
`Exported/Characters` roots in `tests/test_game_core.cpp`,
`test_gap_extent.cpp`, `test_ground_truth.cpp`, `test_one_frame.cpp` and
`test_training_mode.cpp`.

There is no engine directory of the same name, so nothing is overridden. If the
engine ever grows one, the staging script will say so on every build — an
override is allowed and announced, never silent.

> Not to be confused with `tests/fixtures/characters/`, which holds three
> characters transcribed from third-party MUGEN sources. Those are **evidence,
> not content**: this project holds no licence to them, they are deliberately
> outside every asset root, and they must never be staged next to an executable.
> The README beside them records the rule.

### `UntitledFighter/` is namespaced, and everything else of the title's must be

Two reasons, both of them failures rather than preferences:

* **The engine's front end is at `Exported/menu.json` and `Exported/UI/`.** Same
  relative path in two roots means the title wins and the engine's file is not
  staged, so a menu placed at the top level here would not be *adding* a title
  screen — it would be *deleting* the engine demo that a title-less build must
  still boot, and that `tests/test_ui_menu.cpp` asserts on.
* **A top-level `.json` is seed-only: copied when missing, and never pruned.**
  It would therefore survive this title being dropped from the build — a game's
  menu left behind in a runtime directory that no longer contains the game.
  `Characters/` and `UntitledFighter/` are directories, which the staging mirror
  owns end to end and removes in full when the title's `add_subdirectory` goes
  away. Verified: dropping the root prunes exactly those two and nothing else.

So: **put new title content in a subdirectory**, and put it under
`UntitledFighter/` unless it is deliberately taking over an engine path.

## Paths inside these files

Two different conventions, and they are not interchangeable.

| Written in | Resolved against | Example |
|---|---|---|
| A scene's `uiDocument.markup`, a stylesheet's `background-image` | the **host's working directory** | `Exported/UntitledFighter/UI/menu.cxml` |
| `TitleFrontEndScene()`, a character path in the mode or the prover panel | the **content root**, which the host joins | `UntitledFighter/menu.json` |

The second is the one that survives the asset **search path** this whole
layering is interim to: when it lands, nothing is copied over anything, a
shipped title carries its own root wherever it likes, and the host's one join is
the only line that changes.

## Editing

The runtime `Exported/UntitledFighter/` is **mirrored**, so an editor save into
it is overwritten on the next build. Edit here. (Editing the staged copy is
still the way to iterate on a stylesheet live — hot reload picks it up in about
a quarter of a second — but copy the change back before you build.)

`UI/art/title_backdrop.png` is committed so a fresh clone renders the menu with
no asset pipeline, and is regenerated by `../tools/gen_title_art.py`.
