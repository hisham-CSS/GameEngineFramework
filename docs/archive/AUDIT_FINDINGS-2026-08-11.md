# Audit findings

The raw output of a full fan-out audit: 12 readers over the codebase and every
manual page, each claim then handed to a separate agent whose job was to REFUTE
it. 52 survived out of a much larger pile; the refuted ones are not here.

**Every entry is now FIXED.** Each marker says what was done and, where the
defect was testable, names the test that now covers it. The entries are kept
verbatim because the WHY sections are the record of what was actually wrong --
several describe traps the same shape as ones that have recurred, and the
[maintenance guide](MAINTENANCE.md) draws on them.

Note that the WHY text and its line numbers describe the code AS AUDITED. Read
them as history, not as a description of the code today.
Before acting on any entry, re-read it against the source -- the verifiers were
thorough but they are not infallible, and a few overstate the blast radius even
where the mechanism is real.

Each entry is the VERIFIER's reasoning (why it survived refutation) and its
proposed fix. Line numbers were correct at the time of the audit.

Generated by the process described in [MAINTENANCE.md](MAINTENANCE.md).
